# PDF 与内容安全边界

## PDF 转换的实际做法

PDF 的文字通常带有坐标和字体信息，并不直接存储 Markdown 段落。转换器先按页面读取文字块，把纵坐标接近的文字组成一行，再依据行距合并段落、依据相对字号判断标题，并识别常见项目符号和数字列表。中文相邻文字不额外插入空格。这是一个可编辑的初稿，不能推断作者原本的全部语义。

转换器会读取页面绘制操作，提取可用的独立位图并保存为 PNG。图片按页面顺序附到文字后面，因此图文位置需要人工检查。可以在 Markdown 中移动图片行，也可以用资源面板替换或删除；不能编辑图片内部图形。遮罩、复杂裁剪和矢量内容无法保证独立还原。

每页可提取文字少于 8 个字符时，会将页面作为图像保留，不做 OCR。多栏、旋转文字、较多矢量绘制或图片提取失败会触发复杂页面提示，并保留页面图像。少量文字的正常页面也可能落入图像方式，作者可对照原件判断。复杂表格、公式和异常字体编码并不总能自动识别，所以所有转换结果都带有需要对照校验的提示。

PDF 原文件一直作为附件保留。转换失败、加密、页数超限或超时时，可选择“保留原 PDF，不转换文字”。它只检查文件签名和体积，不要求 PDF.js 成功解析；阅读与下载交给浏览器内置 PDF 阅读器。不支持内嵌 PDF 的设备可以直接打开或下载。

资源限制用于减少浏览器内存压力，不能保证所有 20 MB 内的复杂 PDF 都能转换。页面图像最大约 1600×2200 像素，转换最多 40 页。真实样例位于 tests/fixtures，覆盖有文字且含独立图片、纯扫描、两者混合和多栏布局。[PDF.js 官方 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html)

## 导入后的内容不会变成程序

原始文章位于 content/posts，不会作为 VitePress Markdown 页面直接编译。构建脚本仅接收标题、日期和标签，忽略导入的 head、layout 等配置；正文使用关闭 HTML 的 Markdown 渲染器，再通过标签、属性和 URL 协议白名单清理。结果作为字符串进入生成页面，由固定组件展示，不执行 Vue 插值、组件、事件属性或文章里的脚本。

编辑器预览使用无脚本权限的 sandbox iframe，内容安全策略禁止脚本、网络连接、表单和任意资源加载。预览图片只使用已经校验的本地 PNG、JPEG、GIF、WebP 数据。普通文章仍能打开 HTTPS 链接，但外链图片不参与自动加载或发布。

导入路径会检查绝对路径、反斜线、磁盘路径、空段、隐藏路径、编码后的越界和 Windows 特殊文件名。ZIP 使用逐块解压并检查压缩体积、单文件展开体积、总展开体积和文件数量。资源还要通过扩展名与文件签名检查。脚本、HTML、SVG、可执行文件不会复制到文章静态目录。构建再次检查资源并拒绝符号链接；缺失资源会令构建失败。

文件签名检查不是完整的恶意文件扫描。PDF 和图片仍需由维护中的浏览器与解析库处理。当前锁定的 PDF.js 已包含 2026 年公开脚本执行问题的修复；升级依赖后应重新审计与运行样例。PDF 转换不使用交互式脚本执行能力。[PDF.js 安全公告](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j)

安全边界覆盖导入文章。拥有仓库程序写权限的人仍能修改站点 JavaScript；本实现不能阻止恶意浏览器扩展或已被控制的主机读取内存。因此令牌的权限和有效期仍应尽量收窄。
