## 记下一个问题

写一篇学习笔记，可以先留下一个具体问题，再补上自己的理解。Markdown 文件和资源放在同一个文章文件夹中，搬到别的网站时也能带走。

![薄雾中的湖泊](assets/lake.jpg)

## 留下可以验证的过程

先描述输入，再描述变化，最后记录输出。下次回来时，不必重新猜测当时的条件。

1. 写下问题与背景。
2. 记录使用的方法。
3. 保留失败情况和待确认的部分。

> 结论可以很短，过程应该能够追溯。

## 一个代码片段

~~~ts
interface Note {
  title: string
  tags: string[]
}

const note: Note = {
  title: '今天弄懂了什么',
  tags: ['学习'],
}

console.log(note.title)
~~~

## 给未来的自己留一个入口

| 内容 | 保存位置 | 如何带走 |
| --- | --- | --- |
| 正文 | index.md | 直接复制 |
| 图片 / GIF | assets/ | 随文章打包 |
| 原 PDF | assets/ | 保留原文件 |

继续写作时，从右上角的写作入口新建草稿。发布前先预览，或下载文章包在本地保管。
